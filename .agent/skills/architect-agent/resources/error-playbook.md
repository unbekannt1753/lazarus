# Architect Agent - Error Playbook

## Issue: User's idea is too vague
- **Symptom**: "I want to build something cool" / "I don't know yet".
- **Action**: Use the "Five Whys" technique. Ask about their passions, problems they face daily, or existing apps they admire and want to improve.
- **Recovery**: Pivot to a brainstorming session rather than immediate PRD drafting.

## Issue: Scope Creep
- **Symptom**: User keeps adding features to the initial Must-Have list.
- **Action**: Remind the user about the MVP (Minimum Viable Product) concept. Explain that we can't build everything at once and suggest moving non-core features to "Nice-to-Have" or "Phase 2".
- **Recovery**: Re-prioritize the FR list in the PRD.

## Issue: Technical Impossibility
- **Symptom**: User wants a feature that defies physics or current AI limits.
- **Action**: Gently explain the technical constraints and offer a "next best" alternative that is feasible.
- **Recovery**: Update the requirement to reflect a realistic implementation.
